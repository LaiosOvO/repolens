# 质量门清单

写 `stages/03-quality-check.md` 时逐项核对，标注通过/未过及证据位置。任何一项未过，回到稿件修改。

## 结构门

- [ ] 开场 3 句内出现具体痛点场景（有人、有事、有卡点）；
- [ ] 一集只有一个核心知识点，能用一句话说出；
- [ ] 主比喻只有一个，且先讲透生活场景再落技术点；
- [ ] 主体是编号清单式展开（"第一个……第二个……"），点数为 3（long 可到 4）；
- [ ] 有口述实战演示，且演示案例是仓库最普适的功能；
- [ ] 结尾三点式回顾与主体三点一一对应；
- [ ] 有明确的收尾动作：行动指令 + CTA/下集预告（按配方）。

## 事实门

- [ ] 稿件中每条命令、每个配置项、每条路径都能在 `01-evidence.md` 中找到，且带 `文件:行号`；
- [ ] 所有数字（性能、耗时、star、比例）有来源；没有来源的数字已删除或改为定性描述；
- [ ] 没有臆造参数、 flag 或报错信息；证据不足处使用"（视频中未展开）"式标注或未写入稿件；
- [ ] 标题中的承诺在正文中兑现（标题说"分身术"，正文就讲并行）。

## 口播门

- [ ] 逐字朗读无一口气读不完的句子；
- [ ] 全文无"本文/如图/综上/赋能/抓手"等书面语；
- [ ] 英文术语首次出现均有中文注解；命令有中文读法；
- [ ] 字数与 LENGTH 匹配：short ≈800、standard ≈2200–2800、long ≈4000–9000；预估时长 = 字数 ÷ 400–430 字/分钟；
- [ ] 口头禅按配方出现且位置正确（转场"那么问题就来了"、强调"这就很关键了"、解释前"我打个比方你就明白了"）。

## 教学门

- [ ] 一个没用过该项目的人读完能复述：项目解决什么问题、第一步敲什么命令；
- [ ] 演示步骤观众可以照做并得到相同结果；
- [ ] 每个坑都带解决办法，不是只抛问题；
- [ ] 系列稿：第 1 集是"跑起来"，集间顺序符合真实使用路径。
