# 仓库教程视频稿件生成器

由当前 agent 本体执行：读源码取证、设计教学主线、撰写稿件，全部由 agent 完成，不依赖任何稿件生成程序或辅助脚本。需要仓库取证深度合同时，可复用同仓 `skills/repository-report` 的 references（coverage / chapter / narrative-good-bad）作为取证标准，但不得调用任何渲染器或流水线程序。

## 输入

从用户请求取得：

- `SOURCE`：源码仓库绝对路径（必填）；
- `OUTPUT`：输出目录绝对路径（缺省时在 `SOURCE` 父目录创建 `{repository-name}-tutorial-script/`）；不要写入上游源码仓库；
- `STYLE`：`tutorial`（默认，教程式，对应"教你用"）、`teardown`（拆解式，对应"讲透这个项目"）、`interview`（面试题式，把仓库知识点转成面试问答）；
- `LENGTH`：`short`（约 800 字 / 1.5 分钟）、`standard`（默认，2200–2800 字 / 5–7 分钟）、`long`（4000–9000 字 / 10–22 分钟体系课）；
- `EPISODE`：单集（默认）或系列；系列时需产出 `00-系列大纲.md`，每集只讲一个核心知识点；
- `LANGUAGE`：默认简体中文。

## 固定顺序

完整读取 [style-recipes.md](references/style-recipes.md) 和 [teaching-spine.md](references/teaching-spine.md)，按以下顺序执行；每完成一阶段原子写入产物：

1. **仓库取证**，写 `stages/01-evidence.md`：
   - 机械枚举公开入口（README 声明、CLI 命令、配置文件、目录结构、示例、测试），不靠模型取样挑选；
   - 提取稿件所需的全部"可操作信息"：安装命令、最小运行步骤、关键配置项、典型用法、常见报错；每条必须带 `文件:行号` 证据，命令必须来自源码/README 原文，禁止臆造；
   - 提取"教学素材"：这个项目解决什么真实痛点、新手最容易误判什么、有哪些可感知的数字（规模、耗时、性能、star 数须有来源）；
   - 证据不足的点标注 `[视频中未展开]`，写稿时不许编。
2. **教学主线设计**，写 `stages/02-spine.md`：按 [teaching-spine.md](references/teaching-spine.md) 选定本集唯一核心知识点、主比喻（生活化、非程序员也懂）、三个展开场景、一个演示案例（选仓库最普适的功能）、至多三个坑。系列稿要为每集重复此设计并保证递进。
3. **写稿**，写 `manuscript.md`（系列稿为 `ep{N}-{主题}.md`）：严格按 [style-recipes.md](references/style-recipes.md) 中选定 `STYLE` 的配方写。稿件是**口播稿**：全文口语短句，不出现"本文""如下图"等书面语；命令用中文读法标注（如"斜杠 compact"）并在括号内保留原文。
4. **质量门校验**，写 `stages/03-quality-check.md`：逐项过 [quality-gates.md](references/quality-gates.md) 清单，任何一项不过就回到第 3 步修改，最多返修 2 轮；仍不过则如实报告未过项。
5. **渲染与实机验收**：把通过质量门的稿件渲染为自包含 `index.html`（提词器式排版：大字号正文、分节锚点导航、命令/配置用代码样式高亮；仅排版已通过的内容，不得改写稿件）。然后用 ego-browser 打开该 HTML 把核心功能完整过一遍并留证：
   - 新建专用任务空间（如 `repo-tutorial-script 验收`），打开本地 HTML 文件；
   - 逐项验证：侧边栏/锚点导航可跳转且零断链、全部章节渲染完整、命令与代码样式正常、无脚本报错（用 `js()` 读 DOM 和 `console` 错误判断，不要只看截图猜）；
   - 对核心界面截图并保存到 `OUTPUT/screenshots/`：首屏全貌、导航展开、至少 3 个核心章节各一张、系列稿另加大纲页；截图文件名标注验证点（如 `nav-anchors.png`、`section-演示.png`）；
   - 验证记录写入 `stages/04-browser-check.md`（验证项、结果、截图路径、发现的问题），完成后用 `completeTaskSpace(name, { keep: false })` 关闭任务空间；
   - 验证未过的项回到第 3–5 步修复重验；ego-browser 不可用时不得跳过，如实报告并保留 HTML 供人工验收。

## 稿件硬性要求

- 一集只讲一个核心知识点；宁可把进阶内容压成清单，也不扩成第二个主题；
- 正文所有命令、配置、路径必须与 `01-evidence.md` 中的证据一致；口播稿中可以省略参数细节，但出现的就必须真实；
- 开场 3 句内必须出现观众可感知的痛点场景；每个主体论点尽量带一个数字或算账；
- 主比喻一集一个，先讲透生活场景再落技术点；
- 结尾必须三点式回顾（与主体三点一一对应）+ 行动指令 + 互动/预告；
- 标题遵循"主题词 — 利益点/比喻"模式（如"Hooks 自动化 — 让 Claude Code 学会自律"），系列稿附序号。

## 完成门

- 逐字朗读稿件，全程没有一口气读不完的长句；
- 把稿件给一个没用过该项目的人，他能复述"这项目解决什么问题、第一步敲什么命令"；
- 随机抽查 3 处命令/配置/路径，均能在仓库中定位到 `文件:行号`；
- 检查清单全部通过；产出包含 `01-evidence.md`、`02-spine.md`、稿件本体、`03-quality-check.md`、`index.html`、`04-browser-check.md` 和 `screenshots/`；
- ego-browser 实机验收已通过：导航零断链、章节渲染完整、核心界面截图齐备且与验证点一一对应；
- 最终返回所有产物绝对路径、稿件字数/预估时长（按 400–430 字/分钟）、证据条数、截图清单和未展开标注项。
