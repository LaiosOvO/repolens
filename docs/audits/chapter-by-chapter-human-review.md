# 人类报告逐章复核记录

日期：2026-08-11  
范围：CLI 新生成的 Pipecat 6 章、Coze 11 章，以及通用 `repo-teacher report` 生成器  
复核者：主执行 Agent（非实现子 Agent）

## 复核方法

每一章都按同一组人类阅读问题检查，而不是只检查 HTML 能否渲染：

1. 标题后的第一句话是否直接说明“本质是什么”，且没有重复标题或“简单来说”。
2. 是否先说明用户最终得到什么，再进入内部代码对象。
3. 交互图是否明确触发者、运行时所有者、输出和下游消费者。
4. 运行步骤是否讲清输入、处理、状态变化、决策、结束和失败，而不是枚举类名。
5. 涉及存储/查询、循环、Graph、语音、Worker、部署时，是否回答该机制的专属问题。
6. 是否区分核心功能与支撑能力；示例、路由、健康检查、UI 原语不能冒充核心产品能力。
7. 机制、难点、复用边界和源码证据是否分层；源码入口必须最后出现。

## 本轮发现的共性问题与模板修复

| 问题 | 人类阅读后果 | 通用修复 |
|---|---|---|
| `plain_summary` 重复章节标题 | 第一屏像机器拼接文本 | 渲染器去掉精确标题前缀和重复的“简单来说”前缀；新版提示也禁止生成该前缀 |
| “30 秒理解”再次复述摘要 | 信息密度高但没有新增答案 | 主卡改为“用户最终得到什么”；运行预览只保留开始和结束，完整步骤放到交互图 |
| 详细章节都标成“业务功能” | 核心旅程和支撑面平铺 | 根据 `core_product_axes` / `supporting_capability_ids` 显示“核心功能”或“支撑能力” |
| 模型给出的章节顺序可能穿插支撑项 | 技术选型读者找不到主线 | 以产品主轴顺序为权威，再追加支撑能力；CLI 在发布前规范化顺序 |
| Pipecat 项目级交互图仍偏组件清单 | 看不见语音帧如何进入 Flow 又如何返回 | 使用新版综合合同重新生成，要求每一步写参与者、输入、判断/处理、输出和跨主轴交接 |
