研究结论

现成方案各借一块，不照搬一个。

Acquire Codebase Knowledge借：事实扫描、证据门、未知项显式标记。不负责产品优先级与复用决定。
Code Tour / CodeTour借：面向角色的有序文件、行和模式导览。解决“怎么读”，不解决“值不值得借”。
DeepWiki借：由用户指定页面目的和重点模块。自动聚类覆盖不等于任务导向讲解。
CodeWiki / RepoAgent借：分层拆解、聚焦模块与增量更新。作为生成底座，不作为默认页面结构。
GitHub / Sourcegraph借：符号、定义、引用与代码图上下文。是索引层，不是最终教学产品。

MVP 边界

第一版做到能做决定、能交接，不做大而全。

必须做到

  • 固定仓库 commit，识别 5–10 个核心能力
  • 生成总—分—总 HTML 和一条黄金路径
  • 功能卡落到关键符号、测试和证据
  • 选择功能并导出 Skill + 人/机索引
  • 关键代码变化时发现索引过期

这一版不做

  • 不做通用 IDE 或自动改参考仓库
  • 不做 ACP、Codex、OpenCode 派单
  • 不追求一次覆盖仓库所有知识
  • 不提前设计完整数据库、服务和知识图谱
